# 论文（paper）

论文全流程库：下载获取、整理为结构化 Markdown、精读分析，全部产物沉淀进同一个论文库，以一份库索引贯穿状态。

## 模式路由（先判断，再读分册）

| 用户诉求 | 模式 | 读的分册 |
|---|---|---|
| 下载论文、找 HTML 或 TeX 源码、记录来源链接 | 仅下载 | `references/download.md` |
| 论文转结构化 Markdown、整理目录里的论文 | 仅整理 | `references/to-markdown.md` |
| 读论文 / 精读 / 分析论文 | 仅精读 | `references/analysis.md` |
| "下载并整理"、"处理一下这批文献" | 全流水线：下载→整理→精读 | 三个分册都读 |

- 拿不准模式时按用户字面选最小范围，只有明显多步的含糊说法才走全流水线。
- 全流水线的精读段：对每篇整理完成的论文执行 analysis.md 的第一阶段并落盘；第二阶段高阶拓展是交互环节，始终由用户主动逐篇触发，不批量自动做。

## 共享约定（各模式都遵守）

### 库与命名

- 库位置默认当前工作区，用户指定优先。
- 每篇论文一个文件夹：`<会议><年份>_<短名>_<作者缩写>`（如 `ICCV2021_HOZ_Zhang`）；缺会议信息时用 `arXiv<编号>` 或 `<年份>_<短名>_<作者缩写>`，以信息可得为准。
- 源 PDF 与文件夹同名放在文件夹内；HTML 存 `<文件夹名>.html`；TeX 源码存 `<文件夹名>-src.tar.gz`（需要时才解压到 `tex/`）。
- 文件名不带文献编号——编号只活在索引里，便于重排与去重。
- 源文件（PDF、HTML、TeX）一律保留，不覆盖不删除。
- 精读报告落盘为论文文件夹内的 `analysis.md`，是库的合法成员；各模式产出互不干涉，不改动、不清除非本模式产出的文件。

### 库索引（状态的唯一事实源）

库根目录一份 `index.md`，一行一篇，下载与解析两种状态在一张表里贯穿：

```markdown
| # | 标题 | 出处 | 来源页 URL | PDF 直链 | 本地文件 | 下载状态 | 解析状态 | 待核对 |
|---|---|---|---|---|---|---|---|---|
| 1 | HOZ: ... | ICCV 2021 | https://openaccess...html | https://openaccess...pdf | `ICCV2021_HOZ_Zhang/ICCV2021_HOZ_Zhang.pdf` | 已下载（CVF） | 未开始 | — |
| 2 | ... | TIP 2024 | https://ieeexplore.../ | — | — | 仅记 URL（付费墙） | — | — |
```

- `#` 沿用来源文献编号；重复引用合并为一条，编号取首次出现。
- 下载状态取值：`已下载（来源渠道）` / `仅记 URL（原因）`。
- 解析状态取值：`未开始` / `已完成` / `部分完成`。
- 状态一律用纯文字词，不用对勾、叉、旗帜类符号——索引要能 grep、能 diff、能人读。
- 仅下载：产出/续写本表，解析状态留 `未开始`。仅整理：补行补列，不在索引里的散篇论文文件追加行（URL 列填 `—`）。没有索引的库就新建一份。
- 篇级详情（元信息、章节页码映射、待核对位置）放各论文文件夹内的 `index.md`，与库索引并存、职责不同。

### 纪律

- 诚实记录：URL 必须实测或有据（下载成功、HEAD 200、搜索结果佐证），不编造；推断的链接标注"推断"。
- 状态如实两档（已完成/部分完成），不写"已核对完成"这类暗示全量校验的说法。
- 只处理授权范围内的论文和输出。

### 环境

Windows + Git Bash；Python 一律 `uv run` / `uv add` / `uvx`，不找、不装系统 Python。
