# 论文源提取与整理

把论文变成忠实、可 grep 的纯文本源，供后续精读、综述写作和文献检索直接读取。保留原文语言和完整论述；不以摘要、翻译或阅读笔记替代原文。库位置、文件夹命名、索引结构见 SKILL.md 共享约定。

## 两档交付（核心约定）

- **源提取（默认）**：只做确定性转换，交付"文本源 + 报告 + 索引"。模型不做逐字整理。
  - 有 TeX 源码时**什么都不用做**：TeX 本身就是结构良好的纯文本（公式即 LaTeX、章节原生、引用带 bib），解压到 `tex-source/` 即为交付物，不做任何转 Markdown。
  - PDF-only 时跑一次 `scripts/extract_pdf.py split`（即 `extract-pdf split`，console-script 入口），按原文章节切分直接落盘 `markdown-source/`（一节一文件，标题层级、表格由 PyMuPDF `to_markdown()` 内核处理），模型不改动正文。需要整篇单文件时用 `extract --write` 落 `markdown-source/paper.md`。
- **精细整理（按需升级）**：仅当用户明确要求（"整理成结构化 Markdown""按六文件拆分"等）才做，在源提取产物之上切分六文件。源提取产出的 `tex-source/`、`markdown-source/` 保留不动，精细整理产物与之并存。

默认档做完就汇报；不要顺手进入精细整理。

## 输入与状态管理

- 接受指定的论文文件（PDF、TeX 源码、HTML 等格式均可）、论文清单或目录。未指定输入位置时，先向用户确认要处理哪些论文；没有论文时，报告缺少的输入，不以其他论文替代。
- 库索引是状态的事实源：开工先读库根目录 `index.md`（没有就按共享约定新建），从"整理状态"列读续做点；不在索引里的散篇论文，转换前先追加索引行（URL 列填 `—`）。
- 已有输出且源文件未变则跳过或续做；部分完成时从已记录位置继续，保留人工修订，不静默覆盖。
- 保留源 PDF 与源提取产物；只处理授权范围内的论文和输出。

## 来源路由（开工第一步）

按来源决定路径，模型参与度差一个量级：

- **TeX/HTML 路径（arXiv 系论文的默认路径）**：论文有 TeX 源码（`<论文全名>-src.tar.gz`）或 HTML（`<论文全名>.html`）就走这条。源提取档只需解压/落盘交付；精细整理档也以机械转换为主（pandoc 或脚本处理 HTML/tex），模型只做章节映射确认、六文件拼装和校对。**开工时发现 arXiv 系论文缺 TeX/HTML 的，先回 download 子手册补下载，不要直接用 PDF 文本层硬啃公式。**多文件源码包先辨认主 tex（通常含 `\documentclass`，或与论文同名），辨认结果写进 `report.md`。
- **PDF-only 路径（CVF 老论文、IEEE 等无源码来源）**：默认 `extract-pdf split` 按章节切分落盘 `markdown-source/`（切分边界是标题识别初稿，识别不准的章节人工合并/改名即可，不要为此渲染页面）；`outline` 拿标题清单核对，`refs` 拿参考文献切分，`extract --write` 出整篇单文件。公式从 PDF 文本层重建只发生在这条路径上，且只在精细整理档；符号拿不准的照录原文并标注待核对，不猜。

## 默认档（源提取）的输出

```
<文件夹名>/
├── <论文全名>.pdf            # 源文件，论文全名、空格用 _，下载阶段已有
├── tex-source/               # 二选一：有 TeX 源码时，解压 <论文全名>-src.tar.gz 到此
│   └── ...                   #   不做转换，原样交付
├── markdown-source/          # 二选一：PDF-only 时，extract_pdf.py split 的输出
│   ├── 00-front-matter.md
│   ├── 01-introduction.md    #   按原文章节切分，一节一文件
│   └── ...
├── report.md                 # 提取报告（见下）；后续精读报告分节追加到同一文件
└── index.md                  # 篇级索引
```

- `report.md`：从 `references/report-template.md` 复制起稿，填「基本信息」与「提取报告」两节：来源路由结论（走了哪条路径、为什么）、所用工具与日期、章节候选清单（`outline` 输出整理，含页码；TeX 路径则为主 tex 与章节结构概览）、已知问题与待核对事项（指向具体位置与 PDF 页码）。
- `index.md`：元信息（标题、作者、年份、发表信息、标识符）、源文件名与 SHA-256、总页数（无 PDF 时注明）、文件导航、处理状态、待核对摘要。
- 扫描版 PDF（无文本层）例外：才用 OCR 加页面检查，并在 `report.md` 注明。

## 精细整理档（按需）的输出

在默认档产物之上，于论文文件夹根创建以下文件。保留原论文的章节名称、编号和层级；文件分类不代替原始章节结构。

| 文件或目录 | 内容 |
| --- | --- |
| `intro-related-work.md` | 完整 Introduction 和 Related Work；相关工作在引言内部时保留其原位置。 |
| `method.md` | 完整方法，以及服务于方法的问题定义、Background、Preliminaries、模型、算法和训练目标。 |
| `experiments.md` | 完整实验，包括数据集、设置、指标、主结果、消融、定量与定性分析。 |
| `abstract-conclusion.md` | 完整 Abstract 和 Conclusion；Discussion、Limitations 等独立章节保留原名称后归入此文件。 |
| `references.md` | 完整参考文献，保留原编号或作者年份标识，以及原文提供的 DOI、URL 等信息。 |
| `appendices/` | 按原始附录结构或主题拆分的 Markdown；内容很少时可合为一个文件。仅有附录时创建。 |
| `assets/` | 默认不创建、不提取图片；仅当用户明确要求提取图片时创建。 |

- 切分的原料是 `tex-source/` 或 `markdown-source/`（章节文件或 `paper.md`），不是重新读 PDF。
- `references.md` 优先机械转录：TeX 有 `.bib` 或 `thebibliography` 的直接转录；PDF-only 用 `extract_pdf.py refs` 的切分初稿整理。模型只抽查编号与正文引用标识的对应关系。
- 公式：TeX 路径直接引用源码；PDF-only 路径转为 Markdown 可显示的 LaTeX，拿不准的照录原文并标注待核对。
- 表格完整转录：简单表格用 Markdown，复杂表格用 HTML；跨页表格合并为同一逻辑表，保留表头、数值、单位、脚注和加粗强调。
- 默认不提取图片：在原图对应位置保留图号与完整图注文字，并标注物理页码（如 "Figure 2（见源 PDF 第 4 页）"）。
- 来源标记可选，不强制：需要溯源时在每个输出 MD 顶部加一行 `<!-- source: 源文件名 -->`（页码标注按需，PDF 页码可在需要时人工补）。
- 将其余实质内容按用途归入上述文件，并在 `index.md` 记录归属。原文确实没有某类内容时，仍保留四个主体 MD，并注明"原文无独立对应章节"或其实际归属，不补造内容。

## 效率约束（防过度打磨）

- 源 PDF 均有可用文本层，以脚本提取为主，不做 OCR，不做全文渲染比对。
- 提取一律用固定脚本 `scripts/extract_pdf.py`（用法见脚本 docstring），不临场编写提取代码；模型的工作是章节映射、校对与拼装，不是从 PDF 文本层逐字重写正文。
- 渲染页面只用于确认个别读不清的位置，不是常规步骤。逐页渲染目检、覆盖率校验、多分辨率放大取证均不需要。
- 核对以抽查为主：首页、各章节交界处，以及全部编号公式与表格——直接对照已提取的文本即可。
- 状态只分两档：**已完成**（抽查无问题）、**部分完成**（仍有待核对标注）。不使用「已核对完成」一类暗示全量校验的说法。

## 完成标准

默认档交付前检查：`report.md`、`index.md` 齐全；`tex-source/` 或 `markdown-source/` 章节文件就位；待核对项如实标注。

精细整理档交付前检查：四个主体 MD、references.md 齐全；所有原始章节都有归属，无遗漏、无重复；抽查通过（首页、章节交界、编号公式与表格对照文本无异常）。

完成后把本篇的整理状态（可区分"源提取已完成"/"精细整理已完成"）与待核对摘要写回库级 `index.md` 对应行，并向用户报告输出位置、处理状态与待核对内容。
