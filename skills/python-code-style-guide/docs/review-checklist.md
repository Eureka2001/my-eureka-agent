# 代码审查清单

提交代码前，可以按下面的清单快速检查。

## 命名

- [ ] 变量名和函数名能够说明用途。
- [ ] 函数名使用动作语义，布尔名称能够看出真假含义。
- [ ] 类名使用大驼峰，常量使用全大写下划线。
- [ ] 没有无意义的 `data1`、`temp2`、`result_new`。
- [ ] 内部接口使用单前导下划线。

## 结构

- [ ] 每个函数只有一个主要职责。
- [ ] 复杂条件已经拆成有含义的中间变量或辅助函数。
- [ ] 模块没有在导入时执行主业务或昂贵操作。
- [ ] 没有因为图省事而把无关功能堆入 `utils.py`。

## 接口与类型

- [ ] 公共接口有参数类型和返回类型。
- [ ] 没有可变默认参数。
- [ ] 参数优先接收合理的抽象类型。
- [ ] 返回值形式保持一致。
- [ ] `Any` 的使用确有必要。

## 异常与资源

- [ ] 捕获了具体异常，而不是裸 `except`。
- [ ] `try` 块范围足够小。
- [ ] 异常转换保留了异常链。
- [ ] 公共参数校验没有依赖 `assert`。
- [ ] 文件、锁和连接使用上下文管理器。

## 文档与测试

- [ ] 公共接口有准确的文档字符串。
- [ ] 注释解释原因，而不是重复代码。
- [ ] 日志没有泄露敏感信息。
- [ ] 测试名称说明条件和预期行为。
- [ ] 测试不依赖执行顺序或不稳定外部状态。

## 自动检查

- [ ] `ruff check .` 通过。
- [ ] `ruff format . --check` 通过。
- [ ] 项目类型检查通过。
- [ ] 项目测试通过。
