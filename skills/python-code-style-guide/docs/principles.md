# 基本原则

## 可读性

代码被阅读的次数通常远多于被编写的次数。代码首先应该便于人理解，其次才是减少字符数量。

（1）优先编写含义明确的代码，不要追求过度简短。

```python
# 不推荐
x = [i for i in d if i.a and not i.b]

# 推荐
active_users = [
    user
    for user in users
    if user.is_active and not user.is_blocked
]
```

（2）避免让读者依靠上下文猜测名称的含义。

```python
# 不推荐
def calc(x, y):
    ...

# 推荐
def calculate_distance(start_point, end_point):
    ...
```

（3）代码结构应直接表达业务步骤，不要依赖大量注释解释晦涩实现。

## 一致性

风格规则的优先级如下。

1. 同一函数或模块内的一致性
2. 同一项目内的一致性
3. 本指南的一致性

项目已有明确规范时，应优先遵守项目规范。不要只为了满足格式规则而破坏兼容性或降低可读性。

## 自动化

能够由工具统一完成的事情，不应依赖人工反复检查。

- 使用格式化工具统一缩进、换行和引号。
- 使用 Linter 检查未使用导入、未定义名称和常见错误。
- 使用类型检查器检查接口类型。
- 在提交代码前和持续集成环境中执行相同的检查。
